# ServiceCRM — Контекст проекта

## Что это
Мобильное веб-приложение (PWA) для управления заявками в сервисной компании.
Рассчитано на 2-3 человека: оператор (принимает заказы), менеджер (осмотр/оценка), исполнитель (выполнение работ).

## Текущая версия
**v1.0.1** (последний деплой: 11 сентября 2026)

## Стек технологий
- **Фронтенд**: чистый HTML/CSS/JS в одном файле (index.html)
- **Хостинг**: GitHub Pages (https://shamgonov.github.io/Service-CRM/)
- **PWA**: manifest.json + service worker для установки на телефон
- **Realtime-обновления**: баннер появляется автоматически при новой версии

## Версионирование
Формат: **x.y.z**
- z = счётчик деплоев (0-9)
- при z=10: z→0, y+1
- при y=10: y→0, x+1
- Пример: 1.0.9 → деплой → 1.1.0

## Система версионирования
Каждый деплой:
1. Автоматически увеличивает версию (bump.ps1)
2. Перепатчивает файлы с новой версией (patch.ps1)
3. Создаёт git коммит с сообщением "деплой vX.Y.Z"
4. Пушит на GitHub (force-with-lease)
5. Приложение у сотрудников само подхватывает через 30 сек (баннер "Обновление v...")

## Управление проектом
Запусти `tools\menu.bat` — откроется интерактивное меню:
- [1] Создать бэкап текущей версии
- [2] Список всех бэкапов
- [3] Восстановить из бэкапа
- [4] Патч приложения (баннер + realtime)
- [5] ДЕПЛОЙ GitHub (версия +1, коммит, пуш)
- [6] Деплой Firebase (не подключён)
- [0] Выход

## Текущий функционал приложения
- 5 экранов: авторизация, список заявок, детали заявки, создание заявки, календарь
- 4 роли: админ, оператор, менеджер, исполнитель (выбираются кнопками)
- Статусы заявок: новая, осмотр, согласована, в работе, ожидание материала, выполнено, оплачено
- Материалы: учёт с дедлайнами, статусами закупки, местом покупки
- Доп. работы: добавление позиций с пересчётом итога
- Фотоотчёт: обязательный/необязательный флаг
- Дележка прибыли: % для каждого работника
- Данные хранятся в localStorage браузера (каждое устройство независимо)

## Журнал инцидентов и исправлений

### 11.09.2026 — Маркеры git-конфликта в index.html
- **Проблема**: при деплое с git pull возник конфликт слияния, маркеры <<<<<<< HEAD попали в файл и запушились на GitHub. Приложение открывалось криво.
- **Причина**: локальный репозиторий создавался заново через git init при уже существующем удалённом репозитории.
- **Фикс**: убран git pull из деплоя, используется только --force-with-lease. Добавлена проверка: деплой останавливается, если в index.html найдены маркеры конфликта.

### 11.09.2026 — Пустой index.html из-за here-string в терминале
- **Проблема**: вставка большого here-string с кириллицей прямо в терминал PowerShell привела к ошибке "SplattingNotPermitted" (интерпретация @var = @' как splatting), файл записался пустым.
- **Причина**: PowerShell-терминал некорректно парсит here-strings большого размера с UTF-8.
- **Фикс**: большие файлы создаются через VS Code (File → New File → вставить код → сохранить как UTF-8). Это единственный надёжный способ.

### 11.09.2026 — Кракозябры в bat-файлах
- **Проблема**: bat-файлы в UTF-8 читались cmd.exe в cp866, русский превращался в ?????.
- **Фикс**: menu.bat заменён на PowerShell-версию (menu.ps1) с корректным UTF-8 выводом через $OutputEncoding = [System.Text.Encoding]::UTF8.

### 11.09.2026 — Не устанавливается PWA на телефон
- **Проблема**: браузер не предлагал установку приложения.
- **Причина**: отсутствовал icon.png, manifest считался невалидным, service worker падал.
- **Фикс**: icon.png генерируется скриптом через System.Drawing (512x512, синий фон + "CRM").

### 11.09.2026 — Успешное восстановление после пустого index.html
- **Финальное решение**: файл index.html (37+ КБ) создаётся вручную через VS Code (вставка кода), а не через here-strings в PowerShell.
- **Причина**: PowerShell-терминал некорректно парсит большие here-strings с кириллицей, файл записывается пустым.
- **Правило на будущее**: большие файлы (>5 КБ) с кодом создаются только через VS Code. Автоматизация — для патчей, деплоя, бэкапов.

### 11.09.2026 — Мусор в строке APP_VERSION после патча
- **Проблема**: регулярка в patch.ps1 заменяла только часть строки, оставались лишние кавычки: `const APP_VERSION='1.0.5'; ';` → синтаксическая ошибка JS, приложение не запускалось (VS Code показывал "'; expected.").
- **Фикс**: регулярка заменена на полную строку: `const APP_VERSION=[^\r\n]*` → `const APP_VERSION='X.Y.Z';`. Мусор невозможен.

### 11.09.2026 — Нет иконки установки на телефоне
- **Проблема**: браузер открывает обычную страницу, пункта «Установить приложение» нет.
- **Причина**: отсутствовали icon.png / icon-192.png → manifest невалиден → service worker не ставился (404 в списке кэша) → браузер не считал сайт PWA.
- **Фикс**: иконки 192 и 512 px генерируются скриптом (System.Drawing), manifest обновлён с обеими иконками (purpose: any maskable).

### 11.09.2026 — НОВОЕ ПРАВИЛО: локальная проверка перед деплоем
- Любое изменение сначала проверяется локально: http://localhost:8000 (tools\server.ps1)
- Только после локальной проверки — деплой (menu.bat -> 5)
- Версия приложения теперь видна в шапке экрана входа («Версия v1.0.X»), изменения заметны сразу.

### 11.09.2026 — Баннер обновлений: новая спецификация
- **Проблема**: баннер не показывался (старая логика реагировала только на несовпадение версии при открытой вкладке).
- **Новая логика**: каждый деплой увеличивает счётчик deploy в version.json. Приложение сверяет его с crm_ack в localStorage и показывает баннер ПРИ КАЖДОМ ОТКРЫТИИ, пока пользователь не нажмёт «Обновить».
- **Содержимое баннера**: текст из tools\release_notes.txt (контекст фиксов и решённых проблем); если файла нет — «Плановое обновление №N от дд.мм.гггг чч:мм» (N = номер деплоя).
- **Кнопки**: «Обновить» (применяет и перезагружает), «Обновить позже» (скрыть до следующего запуска).
